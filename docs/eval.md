# 评测约定

先定评测，再谈方法。没有固定评测集与基线，任何「提升」都不可证。

## 1. 评测集

| 项 | 要求 |
|---|---|
| 规模 | 起步 100–200 题，按难度分层；后续只增不减 |
| 类型 | 单跳事实、多跳关联、跨文档对比、需拒答（证据不足）四类 |
| 标注 | 每题给**参考答案 + 必需证据集**（`doc_id` + `block_id` 列表） |
| 来源 | 基于 `diligram-ocr-vlm` 解析后的产物构建，不直接用原始 PDF 人工标 |
| 划分 | dev / test 固定，调参只看 dev；test 不参与任何超参选择 |

拒答题单独统计：答错和该拒未拒是两类不同错误，不能合并成一个准确率。

## 2. 基线

至少三条，缺一不可比：

1. **无检索** — 直接让生成模型回答，用于确认检索确实带来增益。
2. **基础 RAG** — 单轮向量检索 top-k + 拼接生成。
3. **本方法** — 分解 + 混合检索 + 证据整合。

三条必须使用同一个生成模型与同一份提示词模板，否则对比无效。

## 3. 指标

| 指标 | 定义要点 |
|---|---|
| 答案准确性 | 与参考答案比对；含数值时按数值判定，不按字面匹配 |
| 证据召回率 | 必需证据集中被实际召回的比例 |
| 证据精确率 | 引用证据中真正被答案用到的比例 |
| 查询耗时 | 端到端与分阶段（分解/检索/生成）分别记录 |
| 拒答表现 | 该拒未拒率、不该拒却拒率 |

延时要报分位数（p50 / p95），不只报均值。

## 4. 消融

- 去掉关联/图查询，只留语义检索 → 看多跳题的差异
- 去掉问题分解，直接单轮检索 → 看步骤依赖题的差异
- 减少最大跳数 → 看证据召回率与耗时的权衡曲线

## 5. 报告纪律

- 数字必须来自可复跑脚本，脚本与评测集一起进仓库。
- 单次运行的结果不作为结论；给出运行次数或置信区间。
- 失败案例要抽样列出，不能只报总分。
- 不在缺少对照的情况下宣称「优于基线」。
